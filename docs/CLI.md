# The `vibehash` command line

Every command, from the command line's own parser. Generated by `python scripts/cli_docs.py`; edit the help text in `vibehash/cli.py` (or `selftest.py`) and run it again, since `tests/test_cli_docs.py` fails when this file is out of date.

`vibehash` and `python -m vibehash` are the same program. With no arguments at a terminal it opens a menu. `--node` and `--wallet` default to what `setup` saved. Wallet passwords are read from the terminal, or from `$VIBEHASH_PASSWORD` on machines nobody is watching. For the ideas behind the commands, see the [README](../README.md) and the [guide](https://vibehash.org/guide/).

## Global flags

- `-v, --verbose`: log every detail (DEBUG), not just what happens (INFO)
- `--version`: show program's version number and exit

## vibehash setup

Get this computer ready to work: node, wallet, GPU support, stake.

```
vibehash setup [-h] [--node NODE] [--wallet WALLET] [--gpu {auto,skip}] [--stake STAKE] [--yes] [--deepseek {yes,no}] [--models-dir MODELS_DIR] [--models-gb MODELS_GB] [--keep-models {yes,no}] [--tls-fingerprint SHA256] [--tls-ca FILE]
```

Flags:

- `--node NODE`: node address, e.g. 192.168.1.20 or http://node.example:8545.
- `--wallet WALLET`: wallet file to use or create (default ~/.vibehash/wallet.json).
- `--gpu {auto,skip}`: find the GPU and install PyTorch for it. Default: `auto`.
- `--stake STAKE`: stake this much VIBE without asking.
- `--yes`: install GPU support without asking. With no terminal (nohup, Docker, a pod) nothing is asked: the wallet's password comes from $VIBEHASH_PASSWORD, its recovery words go to a file only you can read, and model files take the defaults.
- `--deepseek {yes,no}`: whether `worker` takes DeepSeek work (its ~30 GB of model files) without asking; remembered.
- `--models-dir MODELS_DIR`: where big model files go (default: the drive with the most room).
- `--models-gb MODELS_GB`: the most space they may use, in GB (default 40).
- `--keep-models {yes,no}`: keep them after a job ends (default no).
- `--tls-fingerprint SHA256`: trust the https node's certificate with this fingerprint (how workers trust a self-signed testnet node; ask its operator).
- `--tls-ca FILE`: verify the https node's certificate with this CA file.

Examples:

```bash
vibehash setup
vibehash setup --node 192.168.1.20
VIBEHASH_PASSWORD='choose-one' nohup vibehash setup --yes --deepseek no > setup.log 2>&1
```

## vibehash testnet

Run a whole network on this computer: node, workers and a job.

```
vibehash testnet [-h] [--workers 1-8] [--validators 1-7] [--dir DIR] [--host HOST] [--port PORT] [--job {gpu,small,none}] [--budget BUDGET] [--device DEVICE] [--rounds ROUNDS] [--reset] [--plain] [--evo] [--evo2] [--evo2-rounds N] [--evo-model MODEL] [--register-s SECONDS] [--compute-s SECONDS] [--reveal-s SECONDS] [--verify-s SECONDS] [--min-fee MIN_FEE]
```

Flags:

- `--workers 1-8`: workers mining, each with its own wallet (default 2).
- `--validators 1-7`: validator nodes, on --port and the ports after it; they take turns leading rounds and vote on every block (default 1; fixed when the testnet is first made).
- `--dir DIR`: where its wallets and chain live (default ~/.vibehash/testnet).
- `--host HOST`: address the node listens on (default 127.0.0.1; 0.0.0.0 lets other computers join).
- `--port PORT`: the node's port (default 8545); more validators take the ports after it.
- `--job {gpu,small,none}`: the job template to train (see `job template`), or none: post your own, with `train --node` and the testnet's requester.json wallet. Default: `gpu`.
- `--budget BUDGET`: VIBE per job; a new job is posted when one runs out. Default: `500`.
- `--device DEVICE`: what the workers train on: auto, cpu, cuda, xpu, mps. Default: `auto`.
- `--rounds ROUNDS`: stop after this many rounds (default: run until Ctrl+C).
- `--reset`: delete this testnet's chain and wallets and start over.
- `--plain`: print log lines instead of the live mining dashboard.
- `--evo`: Evo mode: training by evolution, the chain is the model. A network whose genesis takes Evo jobs, training an open model on Countdown puzzles, its blocks holding only seeds and scores (default folder ~/.vibehash/testnet-evo).
- `--evo2`: Evo Hash (Evo v2): the fast recipe on every layer, a short job per task in turn (countdown, arithmetic, arc_easy, then round again), each starting where the last ended (es2.py).
- `--evo2-rounds N`: Evo v2: rounds a job runs, its step size planned over them (default 12: a task's quick early gains, then the next task).
- `--evo-model MODEL`: Evo mode's model: a Hugging Face name, from this computer's cache or downloaded once, or a model's folder (default Qwen/Qwen2.5-0.5B-Instruct, about 1 GB).
- `--register-s SECONDS`: how long a round's register phase lasts (default 3).
- `--compute-s SECONDS`: how long a round's compute phase lasts (default 8).
- `--reveal-s SECONDS`: how long a round's reveal phase lasts (default 3).
- `--verify-s SECONDS`: how long a round's verify phase lasts (default 4).
- `--min-fee MIN_FEE`: smallest fee in VIBE this node relays a transaction for (default 0.0001 VIBE; 0 relays free ones).

Examples:

```bash
vibehash testnet
vibehash testnet --validators 4
vibehash testnet --job none --workers 3 --device cuda
vibehash testnet --evo2
```

## vibehash wallet

### vibehash wallet create

Make a wallet and show its 24 recovery words once.

```
vibehash wallet create [-h] [--out OUT] [--no-password] [--passphrase]
```

Flags:

Flags:

## vibehash genesis

The first block of a new network: who starts with coins, stake and a vote.

### vibehash genesis create

Write a genesis file: chain id, starting balances, stakes, validators and the issuance schedule.

Write the genesis file every node of a new network starts from. Addresses come from `wallet create`. A validator named here needs stake of at least the minimum, from --stake or --bootstrap; a worker needs none when --no-earn-in isn't given, since its first pay becomes its stake. The file's hash identifies the network, so give every node the same file.

```
vibehash genesis create [-h] --chain-id CHAIN_ID [--alloc ADDR=VIBE] [--stake ADDR=VIBE] [--validator ADDR=URL] --out OUT [--economics {mainnet,testnet}] [--bootstrap ADDR=VIBE] [--no-earn-in] [--es] [--starter-job SPEC.json]
```

Flags:

- `--chain-id CHAIN_ID` (required): the network's name, written into every block.
- `--alloc ADDR=VIBE`: an address and the VIBE it starts with (repeatable).
- `--stake ADDR=VIBE`: an address and the VIBE it starts with staked (repeatable); staked coins can be withdrawn later.
- `--validator ADDR=URL`: a validator and the address other nodes reach it at (it needs a --stake too). Without any, one node runs the chain alone.
- `--out OUT` (required): genesis file to write.
- `--economics {mainnet,testnet}`: issuance schedule: testnet (fast halvings, for trying things) or mainnet (Bitcoin-like, ~4-year halvings on a busy network); either way only rounds that pay for work mint, and halvings count them. Default: `testnet`.
- `--bootstrap ADDR=VIBE`: stake for a first validator that votes but can never be withdrawn or spent; burned if it leaves.
- `--no-earn-in`: require workers to be given stake; by default they can start with none and earn it.
- `--es`: let Evo jobs run on this network ("es": true); it can't be turned on later.
- `--starter-job SPEC.json`: a job on chain from block one, owned by nobody, paying only new coins (fee 0), so the network can mine with no starting coins; a spec as `vibehash job template` writes.

Examples:

```bash
vibehash genesis create --chain-id my-testnet-1 --out genesis.json --bootstrap NODE_ADDR=10 --validator NODE_ADDR=http://192.168.1.20:8545 --alloc REQUESTER_ADDR=500
```

### vibehash genesis check

Hold a genesis file against what a network meant to carry value needs.

```
vibehash genesis check [-h] [--json] file
```

Arguments:

- `file`: the genesis file to check.

Flags:

- `--json`: print the findings as JSON, for scripts.

## vibehash node

Run a node: serve the chain to workers, and validate if its wallet is a validator.

```
vibehash node [-h] --genesis GENESIS --wallet WALLET --data-dir DATA_DIR [--host HOST] [--port PORT] [--peer URL] [--announce URL] [--dataset DATASET] [--device DEVICE] [--keep-rounds KEEP_ROUNDS] [--max-job-mb MB] [--register-s SECONDS] [--compute-s SECONDS] [--reveal-s SECONDS] [--verify-s SECONDS] [--min-fee MIN_FEE] [--rate-limit SPEC] [--rate-limit-local] [--max-connections MAX_CONNECTIONS] [--min-client VERSION] [--tls-cert FILE] [--tls-key FILE]
```

Flags:

- `--genesis GENESIS` (required): the network's genesis file (see `genesis create`).
- `--wallet WALLET` (required): this node's wallet; a validator's if it is to vote and lead rounds.
- `--data-dir DATA_DIR` (required): folder for the chain, its records and uploaded checkpoints.
- `--host HOST`: address to listen on (default 127.0.0.1; 0.0.0.0 for other computers).
- `--port PORT`: port to listen on (default 8545).
- `--peer URL`: another node to sync from and gossip to (validators find each other from the chain anyway).
- `--announce URL`: the address other nodes reach this one at, if not --host:--port.
- `--dataset DATASET`: add an .npz dataset to this node's store.
- `--device DEVICE`: where the node checks work its checkers didn't and scores each round: cpu (default), auto, cuda, xpu or mps. Fine-tunes want a GPU here (and PyTorch).
- `--keep-rounds KEEP_ROUNDS`: rounds whose opened checkpoints stay downloadable, so anyone can re-run their checks (default 10).
- `--max-job-mb MB`: relay only jobs whose model, one checkpoint at the job's precision, is at most this big (default 64, which a 2 GB server can run; jobs may be up to 1024).
- `--register-s SECONDS`: how long a round's register phase lasts (default 3).
- `--compute-s SECONDS`: how long a round's compute phase lasts (default 20).
- `--reveal-s SECONDS`: how long a round's reveal phase lasts (default 5).
- `--verify-s SECONDS`: how long a round's verify phase lasts (default 10).
- `--min-fee MIN_FEE`: smallest fee in VIBE this node relays a transaction for (default 0.0001 VIBE; 0 relays free ones).
- `--rate-limit SPEC`: per-client request limits: default, off, or overrides like tx=1/10,read=100 (requests a second/burst; buckets: read, worker, tx, upload, other). Clients on this computer are never limited.
- `--rate-limit-local`: limit clients on this computer (127.0.0.1) too, e.g. behind a reverse proxy, where everyone looks local.
- `--max-connections MAX_CONNECTIONS`: connections served at once (default 256).
- `--min-client VERSION`: the oldest Vibe Hash release whose workers may register (default 0.5.14); older ones are told to upgrade. Releases from before this option send no version and are taken as before.
- `--tls-cert FILE`: serve HTTPS with this PEM certificate (see `tls cert`).
- `--tls-key FILE`: the certificate's private key.

Examples:

```bash
vibehash node --genesis genesis.json --wallet node.json --data-dir node-data --host 0.0.0.0
vibehash node --genesis genesis.json --wallet bob.json --data-dir bob-data --host 0.0.0.0 --announce http://203.0.113.7:8545 --peer http://192.168.1.20:8545
```

## vibehash worker

Contribute compute and earn VIBE.

Mine: train and check other workers' units, and earn VIBE. One worker trains on one device. For several GPUs in one computer or pod, run one worker per GPU, each with its own wallet (two with one wallet would undo each other's work, so the second refuses to start): `vibehash wallet create --out gpu1.json`, then `vibehash worker --device cuda:1 --wallet gpu1.json`. Each wallet gets its own cache; the model files they download are shared. With no terminal (nohup, Docker, a pod), set $VIBEHASH_PASSWORD to unlock the wallet.

```
vibehash worker [-h] [--node NODE] [--wallet WALLET] [--device DEVICE] [--memory-mb MEMORY_MB] [--flops FLOPS] [--cache-dir CACHE_DIR] [--plain] [--deepseek {ask,yes,no}] [--job JOB]
```

Flags:

- `--node NODE`: node address (default: the one `setup` saved).
- `--wallet WALLET`: wallet file (default: the one `setup` saved).
- `--device DEVICE`: auto (first GPU found, else CPU), cpu, cuda, cuda:1, xpu, mps. One device a worker: a second GPU gets its own worker and wallet. Default: `auto`.
- `--memory-mb MEMORY_MB`: override detected memory.
- `--flops FLOPS`: override benchmark.
- `--cache-dir CACHE_DIR`: where checkpoints, datasets and receipts are kept (default ~/.vibehash/cache/WALLET-ADDRESS: one per wallet).
- `--plain`: print log lines instead of the live mining dashboard.
- `--deepseek {ask,yes,no}`: take DeepSeek work (its ~30 GB of model files): ask once (the default), yes without asking (unattended), or no. Remembered.
- `--job JOB`: mine only this job's rounds and sit the other jobs' out (default auto: every job this worker can do). The dashboard's job line changes it while it runs: Tab or 0-9.

Examples:

```bash
vibehash worker
vibehash worker --device cuda:1 --wallet gpu1.json
vibehash worker --job fruit-demo
VIBEHASH_PASSWORD='choose-one' nohup vibehash worker --plain > worker.log 2>&1 &
```

## vibehash post-job

Post a training job from a job file, paying its budget in (`train` writes the file for you).

Post a job the network trains round by round until its budget is spent. The budget leaves your balance now and is paid out only for work that passes its checks; `cancel-job` returns what is left. `job template` writes a starter file, and the guide explains every field.

```
vibehash post-job [-h] [--node NODE] [--wallet WALLET] --spec FILE --budget VIBE [--dataset FILE] [--fee FEE]
```

Flags:

- `--node NODE`: node address (default: the one `setup` saved).
- `--wallet WALLET`: wallet file (default: the one `setup` saved).
- `--spec FILE` (required): the job file (JSON).
- `--budget VIBE` (required): VIBE to spend on it, in all.
- `--dataset FILE`: an .npz dataset to upload to the node and train on.
- `--fee FEE`: transaction fee in VIBE, paid to the block's proposer (default: the node's minimum).

Examples:

```bash
vibehash post-job --spec job.json --budget 150 --dataset examples/demo-dataset.npz
```

## vibehash train

Train a model on a CSV file: posts it as a job for the network to train.

```
vibehash train [-h] [--base MODEL] [--rank RANK] [--lr LR] [--max-len MAX_LEN] [--units UNITS] [--yes] [--label LABEL] [--evo] [--budget BUDGET] [--fee FEE] [--hidden HIDDEN] [--id ID] [--node NODE] [--wallet WALLET] [--plain] [data]
```

Arguments:

- `data` (optional): CSV with a header row: numeric input columns, plus the column to predict (on a terminal, leave it out to pick a model from a menu).

Flags:

- `--base MODEL`: fine-tune an open-weight model on a file of chats or text (JSON lines of {"messages": [...]} or {"text": ...}): a name from `models`, org/name or a huggingface.co address. Without a data file, shows what the model would take.
- `--rank RANK`: fine-tunes: LoRA rank (default 16).
- `--lr LR`: fine-tunes: Adam's learning rate (default: by model size).
- `--max-len MAX_LEN`: fine-tunes: longest sequence in tokens; longer chats are cut (default 512, at most 2048; longer sequences make disputes too big to play from home).
- `--units UNITS`: fine-tunes: units of training a round (default 8).
- `--yes, -y`: fine-tunes: don't ask before checking weights or posting.
- `--label LABEL`: the column to predict (default: the last one).
- `--evo`: Evo mode: post an Evo job, training --base (default Qwen/Qwen2.5-0.5B-Instruct) by evolution on puzzles the chain draws, no data file. For local test networks for now (`testnet --evo`).
- `--budget BUDGET`: VIBE to spend, paid only for work that passes its checks (default 100).
- `--fee FEE`: VIBE per round of training (default 10; an Evo job's 1).
- `--hidden HIDDEN`: hidden layer widths (default 128,128).
- `--id ID`: job name (default: from the file name).
- `--node NODE`: node address (default: the one `setup` saved).
- `--wallet WALLET`: wallet file (default: the one `setup` saved).
- `--plain`: print the plan and return, instead of following the job on the live training dashboard (piped output does this anyway).

Examples:

```bash
vibehash train fruit.csv --budget 100
vibehash train my-data.csv --label price --hidden 256,256
vibehash train chats.jsonl --base qwen3-0.6b
```

### vibehash job template

Write a starter job file, for full control with post-job.

```
vibehash job template [-h] [--out OUT] [--id ID] [--gpu] [--evo MODEL] [--tasks TASKS] [--rounds ROUNDS]
```

Flags:

- `--out OUT`: file to write (default job.json).
- `--id ID`: the job's name (default my-first-job).
- `--gpu`: a larger float32 model sized for GPUs.
- `--evo MODEL`: an Evo job on MODEL that never ends, taking its tasks in turn: a genesis starter job (genesis create --es --starter-job).

Examples:

```bash

```

## vibehash chain

Audit the chain yourself, without trusting the node.

### vibehash chain verify

Download every block, re-check it from genesis, and replay every round.

```
vibehash chain verify [-h] [--node NODE] [--genesis FILE] [--no-replay] [--no-recheck] [--receipts FILE]
```

Flags:

- `--node NODE`: node address (default: the one `setup` saved).
- `--genesis FILE`: the genesis file to check the chain against (default: the node's).
- `--no-replay`: skip replaying rounds from their records.
- `--no-recheck`: don't download recent rounds' checkpoints to re-run their weight-based checks.
- `--receipts FILE`: a worker's receipts.jsonl to check (default: every worker's on this computer).

Examples:

```bash
vibehash chain verify
vibehash chain verify --genesis genesis.json
```
